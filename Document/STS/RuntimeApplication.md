# STS 레퍼런스의 런타임 적용

## 입력 파일

- 기준 자료: [STS_ReferenceData.json](STS_ReferenceData.json). 개발 실행에서는 이 원본을 읽는다. 빌드 시 `Content/STS/STS_ReferenceData.json`으로 자동 복사·스테이징하며 해당 생성 복사본은 Git에서 제외한다.
- 운전 가정: [STS_Simulation.json](../../PortSim/Config/STS_Simulation.json). 도면에 없는 기준 좌표·자중·가속도·센서 허용 오차 등을 분리했다. 변경 사항은 다음 실행부터 적용된다.
- `assumed_kg_per_LT`의 long-ton 환산은 명시적 가정이다. 원본의 미확정 `rated_payload_kg`를 수정하지 않는다.

## 자동 운반에 적용되는 내용

| 입력 | 실제 적용 |
|---|---|
| 레일 간격·outreach·backreach | 크레인 다리/레일/빔 배치와 트롤리 이동 한계 |
| 인양 범위 | 작업 목표의 높이 검사와 현수 길이 한계. 지지 높이와 인양 기준점은 가정 파일에 명시 |
| 트롤리·갠트리 속도 | 독립 구동축 속도. 기존 `TravelSpeed*0.6` 결합 제거 |
| 하중별 권상 속도 | 적재 질량에 따라 권상/하강 한계 결정. 빈 스프레더 조건 분리 |
| 메인 권상 모터 정격 출력 | 이상적 기계출력 상한을 이용한 권상 속도 제한. 모터 토크 곡선은 모델링하지 않음 |
| 가속도·저속 착지 속도·감속 거리 | 각 축의 가감속. 이동 구간은 부하별 속도를 사용하고 정지 거리를 고려해 착지 직전 감속 |
| 컨테이너 질량·무게중심 | 물리 바디의 질량/무게중심, 부하 조건과 하중 판정 |
| 트롤리/권상 엔코더 관측 | 자동 위치 제어 입력 |
| 착좌·잠금 상태 | 체결 및 적재 인양 허가 |
| AGV 위치·방향 | STS 하강/인계 허가 및 하강 중 정렬 유지 확인 |
| 화물 지지 관측 | 네 코너 아래 지지면 확인 후 체결 해제·인계 |
| 센서 유효성·주기 | 오래되거나 유효하지 않은 관측이면 자동 운반 중단 |

레퍼런스의 센서 목록을 읽고 필요한 6종을 검증한다. 현재 구현은 엔진 상태에서 생성한 **가상 관측**이며, LiDAR 광학 스캔이나 실제 엔코더 하드웨어 모델은 아니다. 스프레더/화물 자세와 지지면 관측은 자동화에 필요한 추가 합성 관측이다.

네 코너 하중은 질량·무게중심을 이용한 **준정적 분배 추정값**이다. 개별 로드셀의 실제 동적 반력, 개별 와이어 장력 또는 모터 토크를 계산했다는 의미가 아니다. 현수는 기존 Chaos 등가 제약을 사용하고 스프레더 회전은 여전히 잠겨 있다. 흔들림·속도를 확인한 뒤 착지하도록 하지만 제조사 anti-sway/anti-skew 제어기는 아직 구현하지 않았다.

## 실행

1. 저장소 루트에서 `PortSim/Scripts/BuildPortSim.ps1` 실행. 한글 경로에서 발생하는 MSVC 문제를 피하기 위해 임시 영문 junction을 만들며 원본은 이동하지 않는다.
2. 기존 `PortSim/Scripts/LaunchCrane.ps1`로 실행하면 기본 설정에서 초기 안정화 후 자동 하역을 시작한다.
3. U: 하역, L: 역방향 적재, P: 일시정지, Space: 비상정지, R: 초기화. 자동 시작을 끄려면 설정의 `auto_start_unload=false` 또는 실행 인자 `-PortSimManualStart` 사용.

반복 실행용 다른 입력은 `-PortSimSTSReference="경로"`, `-PortSimSTSSettings="경로"`로 지정한다. 잘못된 JSON, 필수 필드/단위 누락, 필수 센서 누락은 자동 운전을 막는다. 현재 기본 컨테이너는 기존과 같은 12t이며 모든 컨테이너에 같은 기본 사양을 적용한다.

하중별 권상 곡선은 도면에 주어진 loaded 점 사이를 선형 보간한다. 최저 loaded 점보다 가벼워도 빈 스프레더 속도로 외삽하지 않고 최저 점의 속도 87m/min을 유지한다. 이 정책 역시 명시한 가정이다.

## 기록과 해석

자동 작업마다 `PortSim/Saved/Results`에 다음 묶음을 생성한다.

- `Terminal_<방향>_<ID>.csv`: 완료 컨테이너, 질량, 작업 소요 시간, STS 동작·준비·AGV/RMG 후속 작업·일시정지 시간, 배치 경과 시간. `STSHandoverAtSeconds`는 STS 인계/배치 확인 시각, `FinalPlacementAtSeconds`는 최종 야드/선박 배치 확인 시각이다. 배치 경과 시간에는 AGV 복귀도 포함되므로 야드 적재 완료 시간에는 마지막 `FinalPlacementAtSeconds`를 사용한다.
- 같은 이름의 `_stages.csv`: 자동화 단계의 종료 시각·활성 시간·완료/중단 상태.
- 같은 이름의 `_profile.json`: 사용한 레퍼런스 전체와 가정 설정, 해석된 적재 한계.

기록은 시뮬레이션 시간이다. 배속에 따른 화면/컴퓨터 실행 시간 감소를 물류 시간 이득으로 계산하지 않는다. 현재 배차는 기존과 같이 한 작업을 STS-AGV-RMG 순서로 완료한 후 다음 작업으로 넘어간다. 병렬 배차 최적화나 기준 운용 대비 시간 절감률은 아직 포함하지 않는다.

## 현재 범위 밖

14종 센서 전체의 상세 물리 모델, 줄걸이별 장력, 모터 전기·토크 응답, 실제 브레이크 동역학, anti-skew 액추에이터, 붐 상승/Catenary trolley, 신축/twin-lift는 자료와 모델 확장 후 적용한다. 레퍼런스에서 읽지 않는 값을 임의로 동작에 사용했다고 표시하지 않는다. AGV/RMG 운반은 기존 위치 추종 방식을 유지한다.

## 검증 도구

`PortSim/Scripts/TestSTS.ps1`는 아래 검증과 센서/잠금/과부하 차단 시나리오를 순차 실행한다. `-Mode Terminal` 등으로 개별 실행할 수 있다.

- Unreal Automation: `PortSim.STS.ReferenceAndInterlocks` (단위 변환·곡선·과부하·작업 범위·센서 유효성·잘못된 입력).
- 기존 `TestTerminal.ps1`: 24개 하역 + 24개 적재, 소유 관계·정지/재개·운반 중 초기화.
- 기존 `TestCrane.ps1`: 독립 크레인 회귀 시나리오. 이 구형 연습 모드는 레퍼런스 확장과 분리되어 있다.
- `-PortSimSTSSensorFault`: 필수 관측 무효화. `-PortSimSTSLockFault=0`: 코너 잠금 실패 주입. 두 경우 자동 운반은 오류 상태로 중단해야 한다.
- `-Mode Overload`: 기본 화물 질량을 100t으로 바꾼 임시 설정으로 운반 전 과부하 차단을 확인한다. `-Mode Faults`는 세 가지 오류 차단만 실행한다.

### 검증 결과 (2026-09-23)

아래 시간 결과는 원본 저장소 `569b9e9` 병합 전 배치 기준이다. 이후 변경된 야드 거리·배치에서는 다시 산정해야 한다.

UE 5.6 Development Editor 빌드 성공. 최종 C++ 빌드에서 프로파일 단위 검사, 24개 하역 + 24개 적재, 독립 크레인 회귀 검사, 센서 무효·코너 잠금 실패·과부하 차단이 통과했다. 오류 검사 도구는 Unreal의 정상 종료가 요청한 실패 코드 1 대신 0을 반환하는 경우를 확인하여, 정확한 실패 사유와 실패 종료 요청 로그를 함께 검사하도록 수정한 뒤 세 오류 검사를 재실행했다.

통합 실행은 `-nullrhi -benchmark -fps=20`의 고정 0.05초 스텝을 사용했다. 화물 소유 관계·목표 슬롯·정지/재개·STS/AGV/RMG 운반 중 초기화, 작업별 시간 합과 배치 누적 시간, 인계/적재 이벤트 순서, 적용 프로파일 스냅샷을 검증했다. 그래픽 화면, 패키징 실행, 여러 배속에서 동일한 결과가 나오는지는 이 검증 범위에 포함하지 않는다.

| 배치 | 마지막 최종 배치 확인 | AGV 복귀 포함 배치 종료 |
|---|---:|---:|
| 선박 → 야드, 24개 | 5,293.250079초 | 5,298.750079초 |
| 야드 → 선박, 24개 | 5,224.500078초 | 5,230.000078초 |

이는 기본 12t 설정과 현재 순차 배차 조건의 **시뮬레이션 결과**다. 하역에는 정지/재개 검사를 위한 의도적 정지 8초가 포함되어 있으며, 실항만 생산성이나 기준 운용 대비 시간 이득으로 해석하지 않는다. 로그는 `PortSim/Saved/Logs/STS_*.log`, 작업·단계·설정 기록은 `PortSim/Saved/Results`에 저장된다.

## 원본 항만 배치와의 통합

원본 `main`의 `569b9e9`까지 병합하여 전체 항만 배치, 선박 컨테이너 액터, 추가 STS/AGV/RMG 물류 흐름을 유지했다. 중앙 `AQuayCrane`의 레일 간격은 STS 프로파일을 따르고, 수면 크기는 원본의 확장 배치를 따른다. 중앙 STS 자동 시작은 프로파일 설정과 `-PortSimManualStart`를 따르며, 별도 `-PortSimSiteTest`에서는 시작하지 않는다.

STS 레퍼런스 적용 범위는 중앙 `AQuayCrane`이다. 원본이 추가한 `APortWorkingCrane` / `APortSiteLogistics`의 전체 항만 운반 모델에는 이번 병합으로 STS 프로파일을 일괄 적용하지 않았다. 해당 경로는 `PortSim/Scripts/TestSite.ps1`로 별도 검사한다.

병합 검증: 변경된 C++ 파일의 컴파일과 Git 충돌·공백 검사는 통과했다. 실행 중인 Unreal Editor가 `UnrealEditor-PortSim.dll`을 사용하여 링크 단계에서 LNK1104가 발생했다. 따라서 병합 후 실행 테스트는 아직 수행하지 않았다. 에디터 종료 후 `BuildPortSim.ps1`, `TestSTS.ps1`, `TestSite.ps1`로 전체 빌드와 두 운반 경로를 검증해야 한다.

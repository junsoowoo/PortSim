# 실시간 돌발상황 관리

기존 ‘실시간 물리 · 돌발상황’ 페이지를 ‘실시간 돌발상황 관리’로 변경했다. 기존 항만 운송·환경·물리·안전 제어를 계속 실행하면서 웹에서 상황을 주입하고 복구 후 실제 작업 완료까지 확인한다. 물리 상세 그래프는 이 페이지에서 표시하지 않는다.

## 사용

1. 최신 엔진 빌드로 시뮬레이션과 대시보드를 실행한다.
2. 대상 장비·문제 상황·발생 조건·지연·복구 요청 시간·제한 시간을 입력하고 ‘장비 상황 추가’를 누른다.
3. 날씨를 입력하고 즉시 적용하거나 조합에 추가한다. 같은 지연 시간의 단계는 함께 실행된다. 날씨 종료는 값을 0으로 하는 별도 단계를 추가한다.
4. ‘조합 실행’ 후 실제 엔진의 적용 응답과 대응·복구·작업 완료 상태를 확인한다. 예약은 브라우저가 아닌 엔진에서 실행되므로 페이지를 닫아도 유지된다.
5. ‘미발생 단계 취소’는 아직 발생하지 않은 단계만 취소한다. 이미 적용된 고장·작업자·날씨와 진행 중 복구 예약은 유지한다. 문제 장비 목록에서 상황별로 복구를 요청할 수 있다.

시나리오당 최대 12개 단계, 한 실행에 최대 24개 기록을 유지한다. 구성은 브라우저에 저장·재사용할 수 있다. 현재 실행에 없는 액터 ID는 실행 전에 다시 선택해야 한다. 실행 기록은 기존 대시보드 JSON 내보내기에도 포함된다.

## 상황과 엔진 연결

| 대상 | 상황 | 작동 방식 |
|---|---|---|
| AGV | 센서 오류 → 재부팅 | 센서 오류 발생 시 관측·이동·신규 배차를 차단한다. 복구 요청 후에만 60초 재부팅을 진행하며, 승인 노드의 관측 재확인 후 정상화한다. 주행 고장은 별도로 유지한다. |
| AGV | 자체 오류 | 기존 구동 고장·예약·화물 보존과 대체 AGV/R/S 복구를 사용한다. |
| AGV | 오배송 지시 | 목적지 지시와 정상 예약의 불일치를 주입한다. 실제 도로를 따라 수신 지점에 도착하면 인수를 차단하고, 수정 후 정상 예약에 인계한다. 다른 야드에 실제 잘못 적재한 뒤 회수하는 모델은 아니다. |
| AGV | 작업자 출현 | 기존 예약된 직선 도로·LiDAR·실제 제동·화물 안정성 경로를 사용한다. 조건부 발생 시 유효한 진입 도로가 나올 때까지 기다린다. |
| STS/RMG | 체결 실패 | 한 모서리 착좌 피드백을 차단한다. 네 잠금·인양 조건은 그대로 유지하며, 가짜 성공을 만들지 않는다. 주입된 정렬 소진은 지지된 화물을 유지하며 다시 취득한다. |
| STS/RMG | 갠트리 고장 | 기존 장비 격리·레일 제약·STS 작업/야드 목적지 재배정 경로를 사용한다. |
| RMG | 적재 착좌 확인 실패 | 하강 단계에서 화물을 유지하며 착좌·해제를 보류한다. 복구 후 기존 하강·착지·정착 조건을 다시 통과해야 한다. |
| 환경 | 비·눈·풍속·안개·결빙 | 기존 공유 환경 컴포넌트의 입력을 바꾼다. 젖음·마름·적설·융설·잔류 결빙과 마찰·센서·기상 운용 제한은 기존 계산을 따른다. |

날씨 입력 범위는 기존 모델에 맞춰 강우/강설 0~100 mm/h, 기준 풍속 0~7 m/s, 안개 시정 0~1000 m(0은 해제), 결빙 입력 강도 0~1이다. 기온과 파도/너울은 팀의 기존 환경 모델을 유지한다. 이 페이지에서 기온·파도 입력은 추가하지 않았다.

## 시간과 검증

### 추가 돌발상황

정상 운송 중 기존 실행을 유지하면서 아래 항목을 즉시 또는 조건부로 주입한다. 별도 시험 장면으로 전환하지 않는다.

| 대상 | 추가 상황 | 실제 대응과 복구 |
|---|---|---|
| AGV | 위치 인식 상실 | Transponder 보정을 차단하고 휠·방위 기반 추정의 오차/불확실성을 누적한다. 1 m/s로 제한하며 불확실성 25 cm에서 제동한다. 해제 후 승인 노드에서 위치를 다시 확인해야 도킹·신규 배차가 정상화된다. 시간당 오차 성장과 1% 휠 오차는 시뮬레이션 가정이다. |
| AGV | FMS 통신 지연 | 새 노드 명령 수신을 2초 지연한다. 미수신 명령으로 이동하지 않고 도착한 명령을 반영한다. |
| AGV | FMS 통신 단절 | 반복 생성되는 명령도 수신하지 못하며 기존 예약·화물을 유지하고 실제 주행 모델로 제동한다. 재연결 후 새 명령 수신을 확인한다. |
| 도로 | 진행 도로 차단 | 선택 AGV의 전방 직선 도로에 차단 구역을 생성한다. 이미 차량이 있는 위치에는 삽입하지 않는다. 모든 차량의 경로 그래프에서 해당 구간을 제외하고 차체 외피를 검사한다. 안전하게 우회할 수 없으면 대기하며 도로 해제 후 재계획한다. |
| STS/RMG | 체결 해제 실패 | 실제 착좌 후에도 잠금을 유지하고 스프레더 이탈·화물 해제를 차단한다. 복구 후 기존 착좌·인계 검사를 통과해야 한다. |
| STS | 호이스트 구동 고장 | 유지 브레이크가 작동하는 고장으로 권상 진행을 보류하고 화물을 유지한다. 브레이크 파손에 의한 자유낙하는 이 항목에 포함하지 않는다. |
| STS | AGV 인계 불가 | 지정 인계 단계에서 연결 확인을 보류하고 하중을 유지한다. 해당 주입으로 기존 정렬 시간 초과를 소비하지 않는다. 해제 후 실제 AGV 정렬을 재확인한다. |
| RMG | 목적 슬롯 점유 | 실제 배정된 슬롯을 외부 점유에 따른 사용 불가 상태로 등록한다. 신규 예약·재배정 대상에서 제외하고 진행 중 적재는 화물을 유지한다. 해제 후 원래 적재 조건을 재확인한다. 임의의 컨테이너를 생성·삭제하지 않는다. |
| RMG | 적재 높이 정보 불일치 | 0.5 m 높이 불일치를 나타내는 주입 상태로 하강·적재를 보류한다. 기존 실제 스택 안전 검사를 통과한 경우에도 이 확인 조건은 별도로 충족해야 한다. |

차단 도로·목적 슬롯은 오버뷰에 표시한다. 각 장비의 개별 돌발상황과 위치 재인식·FMS 응답 대기 상태도 내보내며, 해제는 선택한 상황에만 적용한다. 적용 전부터 존재하던 같은 고장은 새 시나리오가 임의로 인계받아 수리하지 않는다.

- 지연과 복구 요청은 엔진 시나리오 시계를 사용한다. 기상 대기 중에도 진행하고, 수동 일시정지·비상 정지·전체 안전 오류 중에는 멈춘다.
- 조건은 지정 시간, AGV 이동/적재 운반, 크레인 체결/하강 단계다. 조건과 도로가 맞지 않으면 대기하며 제한 시간 이후에는 시간 초과로 남긴다.
- 적용 응답은 검증 성공이 아니다. 실제 정지·관측 중단·체결 차단·적재 보류 등을 관측한 후 오류 해제를 확인하고, 대상 화물의 목적지 도착 또는 후속 작업 완료를 확인해야 통과한다.
- 실제 대응을 관측하기 전에 복구되면 ‘대응 미관측’으로 남긴다. 시간 초과를 고장 해제나 성공으로 바꾸지 않는다.
- 동시 고장의 해제는 상황별로 수행한다. 하나의 자동 복구가 다른 고장을 지우지 않는다. 하중·잠금·충돌 등 실제 안전 오류는 이 제어로 해제할 수 없다.
- 배속 중에도 순방향 고정 단계마다 시나리오 시계와 장비 상태를 갱신한다. 예약·진행 중인 시나리오도 같은 배속 경로에서 처리한다.
- 새 실행/리셋에서 예약·기록·주입 상태를 초기화한다. 화면을 새로고침하는 것은 엔진 리셋이 아니다.

## 센서 오류·장비 자체 오류와 날씨 배치

- 화면의 상황 이름은 ‘센서 오류’다. 오류 발생 자체가 재부팅 완료를 뜻하지 않는다. ‘센서 재부팅 요청’ 또는 설정한 복구 지연 이후 자동 요청으로 재부팅을 시작하고, 재부팅 시간·센서 재확인·후속 작업 완료를 각각 기다린다. 복구 요청까지 0초이면 수동 요청을 기다린다. 기존 명령 키 `fail_reboot`는 호환성을 위해 유지한다.
- AGV는 오류/재부팅/관측 재확인/정상 단계를 내보낸다. STS·RMG는 기존 재부팅 시간과 자체 점검 시간을 사용한다.
- 장비 자체 오류는 센서 오류와 별개다. AGV는 기존 구동 정지, STS·RMG는 제어기 정지·유지 브레이크·장비 격리로 연결한다. 센서 재부팅이 장비 자체 오류를 해제하지 않는다. 빈 장비의 미완료 작업 재배정과 매달린 하중 보존은 기존 안전 제약을 따른다.
- 날씨 입력은 상황 구성 위의 가로 패널에 둔다. 비·눈·풍속·안개·결빙을 먼저 설정하고 아래에서 장비 돌발상황을 조합한다. 좁은 화면에서는 입력 열 수를 줄여 표시한다.
